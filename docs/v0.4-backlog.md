# v0.4 Backlog

Deferred items with rationale and entry points. Everything here was
deliberately left out of 0.3.0 (see `docs/v0.3-release-readiness.md` §1
caveats and §6). Nothing below is a known data-corruption or hang bug;
each has been triaged, documented, and where applicable given a workaround.

## Test coverage gaps

0. **External tables** — `QueryBuilder::with_external_table` ships the API
   but has zero end-to-end coverage (grep: no test references). Add a live
   test: send a temporary table with the query and SELECT from it, both
   engines, compressed and plain.

## Correctness / protocol gaps

1. **LowCardinality nested key-serialization version 2** — the server uses
   key-serialization version 2 for LowCardinality nested inside other columns
   (e.g. `groupArray(LowCardinality(String))`); all readers reject it
   ("unsupported LowCardinality key serialization version 2"). Support means
   extending `lc_idx_width`/dictionary handling in `connection/io.rs`,
   `sync/protocol/response.rs`, and the shared skip engine.
   Workaround: cast to plain types in the query.
2. **Nested-JSON asymmetry in the sync engine** — the sync buffered
   (uncompressed) parser rejects JSON nested under Array/Map/Tuple/
   Nullable/Variant ("nested JSON columns are not supported in buffered block
   reads") while the compressed path (streaming reader) decodes it. Either
   materialize nested JSON in the buffered parser or reject symmetrically
   with a query-time hint.
3. **Plain-sniff short-body quirk** — a non-conforming plain Data body
   shorter than the 17 sniff bytes can swallow the first bytes of the next
   packet; the wrapper then dies with a protocol error instead of a clean
   diagnostic. Make the sniff length-prefix-aware (needs one extra byte of
   lookahead against the block-info field).
4. **EOF-reporting asymmetry** — the async wrapper surfaces a true
   stream-end over-read as `UnexpectedEof` where sync reports a clean EOF.
   Harmless, but uniform errors would simplify client retry logic.

## Performance (P2 from the algorithmic audit, measured or estimated)

5. **Schema cache clones** — `schema_for_table` deep-copies `TableSchema` on
   every hit and runs up to 3 map lookups (`sync/client.rs:536`). Return
   `Arc<TableSchema>` via `entry()`.
6. **DDL nukes the whole schema cache** — any `query_may_change_schema`
   statement clears every table's entry (`sync/client.rs:631`). Invalidate
   per affected table instead.
7. **Async raw-reader String loop** — `raw_block_reader.rs:460` still reads
   varint+body per row (the P1 fix covered only
   `read_string_column_with_prefixes`). Needs a stream-pushback design so a
   buffered read cannot consume the next column's bytes.
8. **QueryStream column copies** — `parse_block` copies each column out of
   the receive buffer (`response.rs` `to_vec()`); switching QueryStream to
   `parse_block_shared` (zero-copy `Bytes` slices) removes the copy.
9. **Type re-parse per block** — identical type names are re-parsed for every
   column of every block (~100 ns × cols × blocks). Cache `ColumnType` per
   column index once the first block of a response is seen.
10. **Dead BUF_POOL / per-packet allocs** — `sync/client.rs` `BUF_POOL` is
    pop-only (nothing ever returns buffers); either wire a return-on-drop
    guard or delete it.
11. **Async idle-ping stray-Pong drop window** — cancelling `get()` between
    Ping write and Pong read returns a socket with a stray Pong frame to the
    slot. Discard the connection when the ping future is dropped unresolved.

## Larger themes (candidate 0.4/0.5 projects)

16. **Query-scoped cancellation handles** — a `QueryHandle` registry
    (query_id → slot/stream) so "cancel someone else's in-flight fetch"
    becomes possible without the pool-wide discard; today only timeouts,
    owning a stream, or drop-with-discard work (by design in 0.3).
17. **Sync/async parser consolidation** — the shared-include pattern
    (`shared/*.rs`) already unifies wire/skip/type parsing; the remaining
    duplicated column readers (~1.4-1.6 kLOC) are the next consolidation
    step, which would also close items 2, 7 and 9 structurally.
